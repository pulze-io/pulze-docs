<Update label="2.0.20-rc" description="October 25, 2026">
RenderFlow 2.0.20 adds cloud machines, personal sign-in, AI clients and centralized updates, along with fixes across many applications.

**Updates:**
- Cinema 4D 2027 and Blender 5.3 support
- New Cloud machines on AWS and Azure: hybrid rendering alongside your existing machines
- New centralized RenderFlow updates: update every machine from Settings > Deploy
- New Sign in with pulze.io: each person carries their group's permissions (optional)
- Add people in Users before they first sign in
- API keys can be limited to the features they need
- New AI Clients: use RenderFlow from Claude, Cursor, VS Code, Codex or LM Studio
- New Denoise step with Intel Open Image Denoise
- The Image Converter reads single layers from multi-layer EXRs
- Unreal Engine renders real Cryptomatte
- New Nuke Script and Fusion Script steps
- Scheduled scripts: run scripts on your machines on a schedule
- Job groups, and jobs filter by start and finish time
- Backups and restores with your own MongoDB server
- Password-protected exports, and restore from any export file
- Move machines to another server
- Default Python and FFmpeg versions in Settings > Apps
- 3ds Max closes known plugin pop-ups during a render
- Server addresses can include a port, for proxies and tunnels
- Batch jobs can be named by item, file, or both
- Who can render shows what each machine is working on
- Page size options on lists longer than 100 rows

**Fixes:**
- Fixed jobs going to a pool the user group can't submit to
- Fixed machines being moved into a pool the group can't see
- Fixed distributed V-Ray and Corona renders stalling when the main machine fails
- Fixed a resumed machine losing the frame it was rendering
- Fixed Vantage and Autograph batch jobs overwriting each other's images
- Fixed Cinema 4D live previews stopping after the first frame
- Fixed V-Ray Standalone stills on Linux reported with the wrong name
- Fixed DaVinci Resolve image sequences listing only some frames
- Fixed After Effects and Nuke movies listed as one file per frame
- Fixed `_conflicted` job folders on LucidLink
- Fixed 3ds Max jobs changing the artist's output format settings
- Fixed Maya render layers missing from the scene becoming jobs
- Fixed custom `.rs` benchmarks rendering the wrong frame
- Fixed `.rib` scenes being rejected
- Fixed outdated machines taking work after a server update
- Fixed the machine list failing after a benchmark was deleted
- Fixed jobs no machine can render waiting without a reason
- Fixed Rhino, SketchUp and Vantage needing write access to the share
- Fixed the Windows installer cutting `--server` addresses at a hyphen
- Fixed the VRED viewpoint list starting on None
- Fixed Redshift for Houdini not being found
- Fixed Blender scenes on shared drives not opening
- Fixed idle GPUs showing as busy
- Fixed batch submits opening on the scene's current state
- Various stability improvements
</Update>

<Update label="2.0.18-beta" description="October 13, 2026">
RenderFlow 2.0.18 adds benchmarks, node order, live previews for more renderers and VRED Pro and Core, along with fixes for Maya, Cinema 4D, Unreal Engine and the installers.

**Updates:**
- New Benchmarks: run Blender, Cinebench, Redshift, V-Ray or your own scene and save each machine's score
- New Node order: send work to the best machines first, by benchmark, GPU memory, RAM, CPU threads or machine type
- New scene browsing for 3ds Max, Blender, Cinema 4D and Maya, the same as submitting from the application
- Live preview for V-Ray Standalone, Arnold, Cinema 4D and Maya with V-Ray
- New Blacklist: keep machines off one step of a job
- Render licences can exclude machines from the seat count
- VRED Pro and VRED Core support, with the scene's viewpoints, clips and Render Settings
- Nuke and Fusion steps can read an earlier step's render, and write their outputs elsewhere
- Unreal Engine Movie Render Graph and Basic configs
- New `rfsv service install` for the Windows service, and upgrades keep the service
- `rfcli` accepts names instead of ids and prints readable tables
- macOS tells you when Local Network access blocks RenderFlow
- `Ctrl+O` (`⌘O` on macOS) opens a job's output folder, and shortcuts show next to their actions
- Log search highlights every match
- Error messages open in full, with Copy
- The submitter remembers the last folder you browsed and offers each step's output formats
- Version lists show the newest first, and a step asks for exactly the version you pick

**Fixes:**
- Fixed editing several jobs at once giving them all one job's frames
- Fixed a second scene keeping the first scene's settings
- Fixed the last frame of a batch keeping its in-progress preview
- Fixed Cinema 4D frames on Linux counting toward the wrong task
- Fixed Unreal projects missing from Perforce failing with "Scene file not found"
- Fixed Submit staying off when a step's scene comes from an earlier step
- Fixed slow `.vrscene` exports
- Fixed single-frame RenderMan renders not being found
- Fixed slow upgrades on machines with a large cache
- Fixed Show in Explorer for backups
- Fixed the VRED plugin not installing
- Fixed the audit log filling up with retries from removed machines
- Various stability improvements
</Update>

<Update label="2.0.9-beta" description="September 21, 2026">
RenderFlow 2 ships 35 job templates across 20 applications and renderers, on Windows, Linux and macOS. A job is no longer a single render: it is a chain of steps that render, export, convert, encode and run your own scripts, in one submission.

**Platforms:**
- Full macOS and Linux support

**Submitting:**
- Job submitter — a completely redesigned interface
- Multi-step jobs — render, export, convert, encode and script in one submission
- Processing steps — run your scripted jobs with 3ds Max, Maya, Blender, Cinema 4D or Houdini
- Export steps — write `.ass`, `.vrscene`, `.rs` or `.usd` files, then render them with a standalone
- Prompt to job (preview) — describe the job in a sentence and the submitter builds the chain for it
- Custom plugins — create and register your own plugin that becomes a job type in the submitter
- Job templates — save and manage templates centrally in Settings
- Image step — convert between image formats using OpenImageIO
- Video step — encode a sequence with the built-in ffmpeg
- Frame orders — linear, first and last, every nth

**Job types:**
- 17 more applications and renderers: Maya, Houdini, Nuke, After Effects, Unreal Engine, VRED, Chaos Vantage, Premiere Pro, DaVinci Resolve, Adobe Media Encoder, Toon Boom Harmony, KeyShot, RenderMan, Arnold, Redshift, Python and Shell
- Batch submit per state or render item for Houdini, After Effects, Unreal Engine, Chaos Vantage and DaVinci Resolve

**Monitoring:**
- Farm view — every machine and job on one canvas
- Frame gallery — a thumbnail per finished frame, and a live preview of the one still rendering
- Error catalog — common errors explained in plain language, shown inline in the log where they happened
- Audit and Events logs — who did what, and what the farm did on its own
- GPU monitoring — VRAM, temperature and utilization

**Farm and administration:**
- Pool sharing — lend and borrow machines between pools
- Pool admission — allowed job types, priority ceiling, machine limit per job
- Group permissions — 48 features with granular control over who can access certain views, jobs or features
- Render licenses — jobs wait for a free renderer seat instead of failing
- Automation — rule based idle detection, return to user, power-off and wakeup settings
- Notification channels — your own SMTP, error events, and custom Slack, Teams and Discord messages
- Job clean-up — delete or archive jobs automatically, from immediately to a week after they finish
- Offline licensing — run with no internet connection (Enterprise)
- TLS settings — certificate, private key and certificate authority
- Security settings — discovery and allowed addresses
- Per-app custom search paths and environment variables
- Headless server configuration and authentication

**Interface:**
- One design system across every screen — tables, dialogs and settings all behave the same way
- Reworked Settings — every section, from pools and groups to security and notifications
- Handles 1000+ machines and thousands of jobs without slowing down
- Faster filtering, search and sorting

**Developers:**
- One consistent API across every client
- New Webhooks system
- Python SDK for custom job plugins
- Updated Python and TypeScript SDKs
- Updated `rfcli` command line tool
- Updated MCP server

**Changes from RenderFlow 1:**
- Jobs, settings and history are not migrated
- The API and SDKs have changed, so a 1.x integration needs updating
- V-Ray DR and Corona DR are now a Distributed switch in the 3ds Max job type
- Scene Manager states are now submitted from the 3ds Max job type
- The Agentic Jobs and ComfyUI previews are not yet available in the current beta
- Cloud rendering and the deploy feature are not part of RenderFlow 2
</Update>
