---
title: "Create New Document"
description: "Build a new, organized Photoshop document from a template and your render output in one go."
---

**Create new document** takes a folder of render elements and a [template](/layerwise/templates), and builds a new PSD: groups with their colours and blend modes, every render placed as a smart object in its slot, masks cut from your mattes, and placeholders for anything missing.

The wizard has three steps: **Renders → Plan → Done**.

## Before you start

- Select the right render engine on the [Home screen](/layerwise/interface#home).
- Render your elements as separate files (or as a [multichannel EXR](/layerwise/workflows/multichannel-exr)). Keep one camera's renders together in one folder.

## 1. Pick your renders

Press **Create new document** on Home. Then choose:

- **Browse folder** to pick the folder your renders were saved to. LayerWise scans it and all its subfolders (skipping thumbnail folders) for PNG, JPEG, TIFF, TGA and EXR files.
- **Pick files** to choose individual files instead.

LayerWise reads each file's size, resolution and bit depth, and sorts every file into its element by name.

## 2. Check the plan

This step shows everything that will be built, so you can check it before anything happens in Photoshop.

<Frame caption="Step 2, Plan: check the name, saving, template, size and what gets built">
  <img src="/images/layerwise/lw_build_configure.webp" alt="The second step of the Create new document wizard with document settings and the list of what will be built" />
</Frame>

### File

- **Name.** Taken from your beauty pass (RGB_color for V-Ray, Beauty for Corona and FStorm): the file name up to the first dot. Change it if you like.
- **Save next to the renders.** *Off* (the default), *PSB* or *PSD*. With PSB or PSD, LayerWise saves the new document into the render folder when it's built, under its name. An existing file is never replaced: a number is added instead (`cam01 2.psb`). Pick PSB for files over 2 GB. Your choice is remembered.

### Document

- **Template.** The templates of the current engine, with your [default template](/layerwise/templates#default-template) first, then your own and cloud templates, then the built-in ones. The chip shows the template's bit depth. It turns red if it differs from the bit depth of your renders (for example an 8-bit template with 32-bit EXRs).
- **Inspect template** (the eye) shows the template's full layer tree.

If some of your renders have no slot in the chosen template, a warning lists them. They won't be imported, so pick another template or [edit it](/layerwise/template-editor) if you need them.

### Render output

- **Width × Height.** Defaults to the largest render size. Changing it resizes the document after the renders are placed. With the aspect ratio locked (the default), the height follows the width.
- **DPI.** Defaults to the renders' resolution, or 72 if they don't store one. Changing it only changes the document's DPI setting, not its pixels.

### What gets built

- **Elements found.** Every template element with a matching render. When several files match one element, LayerWise uses the last one by default. **Show every match** lets you choose a different file per element. Elements marked *Import all* (such as LightSelect) bring in every matching file.
- **Which file is the Beauty pass?** For Corona and FStorm, the beauty pass often has no element name in it (for example just `cam01.png`). If the template needs a Beauty and none was matched, LayerWise asks you to choose it among the files that matched nothing.
- **Placeholders for N missing elements.** Creates an empty smart object in the slot of every template element you didn't render, so the structure is complete and you can fill them later with [Update renders](/layerwise/workflows/update-renders).
- **Extract N layer masks.** Makes masks from your multimatte and luma passes. The chips show every mask that will be made, such as `#Wood` from a multimatte's nametags or `[LUMA]Alpha` from the Alpha pass. See [Masks](/layerwise/masks). The toggle is disabled when there are no multimatte or luma elements among your renders.
- **Cryptomatte masks.** Shown when your renders include a Cryptomatte. Pick the objects or materials you want masks for, in a list or straight in the image. See [Cryptomatte](/layerwise/cryptomatte).

Files that matched no element are listed under **These files matched no element**. If one of them should be recognized, add its name in [Render elements](/layerwise/render-elements).

Press **Build document**.

## What LayerWise builds

1. A new document at your renders' size and the template's bit depth.
2. The template's groups, top to bottom, each with its name, label colour, blend mode, opacity and visibility.
3. Every render placed as a smart object inside its group, at its native size, with the slot's blend mode and opacity. Multimatte and wire colour layers are hidden, since they are only used for masks.
4. Masks on the matching groups (created where needed), and the same masks saved as alpha channels. Picked Cryptomatte mattes become `#name` groups in the template's Cryptomatte slot.
5. The document resized to your width, height and DPI, if you changed them.
6. If [Layer transforms in new documents](/layerwise/settings#layers) is set to *Reset to 100%*, every smart object is baked so its scale reads 100%.
7. If **Save next to the renders** is on, the document saved as PSB or PSD in the render folder.

## 3. Done

The new document is open in Photoshop. If you chose to save it, the Done step shows where. Press **Build another** to start again, or **Done** to go Home.

## Tips

- **Placed layer names.** By default each layer is named after its file. Choose *Element name* in [Settings](/layerwise/settings#layers) for short names like `Reflection`.
- **Linked or embedded.** Linked smart objects keep the PSD small but need the render files to stay where they are. With *Reset to 100%* on, new documents embed them anyway, because baking a smart object embeds it.
- **Keep the naming.** Don't rename the render element layers to something without the element name, or [Update renders](/layerwise/workflows/update-renders) won't find them later.
