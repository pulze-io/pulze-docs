Everything Scene Manager 3 does goes through the **Scene Manager service**, which runs on your computer next to 3ds Max. The Scene Manager UI uses it, and your scripts and AI assistants can use it the same way: to manage setups and folders, change modules, run batch renders, build variations and work with comments.

## How Scene Manager thinks

- A **setup** is a saved state of the scene: its camera, lighting, resolution, output and so on.
- A setup's values are grouped into **modules**. When a module is off, that part of the scene is left alone.
- Setups can be organized into **folders**, and a folder's values apply to every setup inside it.
- **Activating** a setup writes its values into the open scene. A **batch render** activates and renders each setup in turn.

Scene Manager doesn't create anything in your scene. It works with what is already there and switches between saved states of it.

An operation has the same name everywhere: `GET /setups` is `listSetups` in the [API reference](/scene-manager-3/api-reference/introduction) and `scene.setups.list_setups()` in Python.

## What the API covers

| Area | What you can do |
|---|---|
| Setups and folders | List, create, change and activate setups, and organize them in folders |
| Modules | Add modules (Camera, Output, Lights…) and choose their properties |
| Rendering | Start a batch render, follow its progress, stop it |
| Variations | Render every combination of a set of options |
| Comments and shots | Pin comments on viewport and frame buffer shots, for people and agents |
| Scene | Read the open scene: objects, materials, properties, selection, scripts |
| Document, settings, HDRI library | The whole document, your settings and the HDRI library |

The [API reference](/scene-manager-3/api-reference/introduction) lists every endpoint by area.
